Teact reads configuration from two places. `teact.config.ts` holds **infrastructure** settings: transport mode, webhook, session store, plugins and middleware. `createBot()` holds **your app**: the root component or router, commands and providers, and it accepts every infrastructure field too. Use the config file for settings that differ per deployment, and `createBot()` for everything else, or for everything when you deploy to the edge.

```ts title="teact.config.ts"
import { defineConfig } from "@teactjs/core";

export default defineConfig({
  mode: "polling",
  session: { ttl: 30 * 60 * 1000 },
});
```

```tsx title="src/index.tsx"
import { createBot, createRouter } from "@teactjs/core";
import { TelegramAdapter } from "@teactjs/telegram";
import { storagePlugin } from "@teactjs/storage";
import { Home } from "./pages/Home";

export const bot = createBot({
  router: createRouter({ "/": Home }),
  adapter: new TelegramAdapter(),
  plugins: [storagePlugin({ driver: "file", path: ".teact/storage.json" })],
  commands: { start: { description: "Start the bot", route: "/" } },
});

if (import.meta.main) bot.start();
```

Commands, the `component`/`router` and `providers` are not config fields: they belong in `createBot()`.

### How the file is loaded

- The engine looks in the **current working directory** for `teact.config.ts`, then `teact.config.js`, then `teact.config.mjs`, and imports the first one it finds. Run the bot from the project root.
- It is loaded once, the first time the bot initializes: on `bot.start()`, `bot.setCommands()` or the first `bot.fetch()`.
- On success the console shows `[teact] Loaded teact.config.ts`. If the import throws, Teact logs `[teact] Failed to load teact.config.ts:` with the error and **continues with no config**.
- It is never loaded where there is no filesystem (Cloudflare Workers and other edge runtimes). See [the edge caveat](#the-edge-caveat).

## Precedence rules

When the same setting appears in both places, `createBot()` wins. In detail:

| Setting | Rule |
| --- | --- |
| `mode`, `webhook` | `createBot` value, else `teact.config.ts`, else `"polling"`. `mode: "webhook"` without a `webhook` object starts polling. |
| `session.store` | `createBot` store, else the config file store, else a new in-memory store. |
| `session.ttl` | Only `createBot({ session: { ttl } })` sets the default in-memory store's TTL (milliseconds, default 24 hours). A custom store manages its own expiry. |
| `plugins` | Config plugins first, then `createBot` plugins. A plugin whose `name` is in **both** lists is used once, the `createBot` copy, and Teact warns: `Plugin "…" is in both teact.config.ts and createBot({ plugins }) — using the createBot() one.` Repeats **within one list** are all kept. |
| `middleware` | All run, in this order: plugin middleware, config middleware, `createBot` middleware. |
| `commands` | Commands declared on router routes (`command:`), then `createBot({ commands })`, which overrides a route command with the same name. |
| `token` | `bot.fetch(req, { token })`, else `createBot({ token })`, else `TELEGRAM_BOT_TOKEN`. |

Repeating a plugin in one list is how you layer limits:

```ts title="src/index.tsx"
import { rateLimit } from "@teactjs/plugins";

createBot({
  // ...
  plugins: [
    rateLimit({ key: "user", window: 1000, limit: 3 }),
    rateLimit({ key: "chat", window: 60_000, limit: 60 }),
  ],
});
```

### Provider order

The root element is wrapped from the inside out: your router or component, then each plugin's `Provider` in list order, then your `providers` component as the outermost layer. Your providers can therefore read from plugin contexts.

## Recipes

### Webhook server on your own host

```ts title="teact.config.ts"
import { defineConfig } from "@teactjs/core";

export default defineConfig({
  mode: "webhook",
  webhook: {
    domain: "https://my-bot.example.com",
    port: 3000,
    path: "/webhook",
    secretToken: process.env.WEBHOOK_SECRET,
  },
});
```

`bot.start()` sets the webhook and listens on port 3000. If the port is taken it fails with `Port 3000 is already in use.`

### Polling locally, webhook in production

Keep the code the same and switch on an environment variable:

```ts title="teact.config.ts"
import { defineConfig } from "@teactjs/core";

const isProd = process.env.NODE_ENV === "production";

export default defineConfig({
  mode: isProd ? "webhook" : "polling",
  webhook: isProd
    ? { domain: process.env.PUBLIC_URL!, secretToken: process.env.WEBHOOK_SECRET }
    : undefined,
});
```

`teact dev` sets `NODE_ENV=development` unless you already set it. `PUBLIC_URL` here is your own variable, not one Teact reads.

### A durable session store

```ts title="teact.config.ts"
import { defineConfig } from "@teactjs/core";
import Redis from "ioredis";
import { redisSessionStore } from "@teactjs/redis";

export default defineConfig({
  session: { store: redisSessionStore({ client: new Redis(process.env.REDIS_URL!) }) },
});
```

Check [`@teactjs/redis`](/docs/packages/redis) for the store's full options, and [Databases](/docs/guides/databases) for the other backends.

### Debugging a stuck bot

```ts
createBot({ /* ... */ debug: true });
```

Every update, the middleware count, render and processing time are logged with an ISO timestamp, prefixed `[teact:debug …]`. At startup you also get the mode, command names, plugin names and middleware count.

## The edge caveat

On Cloudflare Workers, Vercel Edge and Deno Deploy you handle updates with `bot.fetch(request, { token, secretToken, env })` instead of `bot.start()`. **There is no filesystem on the edge**, so:

<Callout type="warn">
  `teact.config.ts` is **not** loaded on the edge (loading it needs `fs`). Anything you put there,
  especially `plugins` and `session`, is silently ignored. Pass those options to `createBot()`
  instead.
</Callout>

- **Plugins**: move them into `createBot({ plugins: [...] })`. Scaffolded projects already do this.
- **Session**: the default in-memory store does not persist between requests. Teact logs a warning on the first `bot.fetch()` when it is in use. Use a durable store: `d1SessionStore` / `kvSessionStore` ([`@teactjs/cloudflare`](/docs/packages/cloudflare)), `redisSessionStore` with Upstash ([`@teactjs/redis`](/docs/packages/redis)), or `postgresSessionStore` with Neon ([`@teactjs/postgres`](/docs/packages/postgres)).
- **Storage**: the `'file'` driver can't write on the edge (it warns and degrades to memory). Pass an edge-capable driver (`D1Driver`, `KVDriver`, `RedisDriver`, `PostgresDriver`) to `storagePlugin`.
- **`.env`**: not read. Set `TELEGRAM_BOT_TOKEN` and `WEBHOOK_SECRET` as platform secrets and pass them to `bot.fetch()`.

```ts title="src/worker.ts"
import { createBot, getEnv } from "@teactjs/core";
import { TelegramAdapter } from "@teactjs/telegram";
import { storagePlugin } from "@teactjs/storage";
import { D1Driver, d1SessionStore } from "@teactjs/cloudflare";
import { router } from "./router";

interface Env {
  TELEGRAM_BOT_TOKEN: string;
  WEBHOOK_SECRET?: string;
  DB: D1Database;
}

const bot = createBot({
  router,
  adapter: new TelegramAdapter(),
  plugins: [storagePlugin({ driver: new D1Driver(() => getEnv<Env>().DB) })],
  session: { store: d1SessionStore(() => getEnv<Env>().DB) },
});

export default {
  fetch: (request: Request, env: Env) =>
    bot.fetch(request, { token: env.TELEGRAM_BOT_TOKEN, secretToken: env.WEBHOOK_SECRET, env }),
};
```

`getEnv()` returns the `env` passed to the most recent `bot.fetch()`, so lazy getters created at module scope can reach your bindings. It throws if called before the first `bot.fetch()` with an `env`. Full walkthrough in [Deployment](/docs/guides/deployment).

## Environment variables

| Variable | Read by | Notes |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | `createBot`, `teact doctor`, `teact webhook` | Required unless you pass `token`. Always this name. |
| `WEBHOOK_SECRET` | `teact webhook set`, `teact doctor` | Not read by `createBot`: pass it as `webhook.secretToken` or `bot.fetch(req, { secretToken })`. `teact doctor` warns when it's missing in a webhook or Workers project. |
| `PAYMENT_PROVIDER_TOKEN` | Your code (the scaffolded Store page) | Passed to `useInvoice({ providerToken })`. See [Payments](/docs/guides/payments). |
| `REDIS_URL`, `DATABASE_URL` | Your code (scaffolded with `--db redis` / `--db postgres`) | Connection strings for the generated drivers. |
| `NODE_ENV` | Set by `teact dev` | Defaults to `development` in dev. |

How `.env` is loaded:

- **At runtime on Bun or Node**, `@teactjs/core` reads `.env` from the working directory when it is imported. It skips blank lines and `#` comments, strips surrounding quotes, and **never overrides** a variable that is already set.
- **Under `teact dev`**, Bun also auto-loads `.env.development` and `.env.local` from the project root.
- **The CLI commands** `teact doctor` and `teact webhook` check the process environment, then `.env.local`, then `.env`.
- **On the edge** nothing is loaded; use platform secrets.

## Do and don't

- **Do** keep `mode`, `webhook`, `session`, `plugins` and `middleware` in `teact.config.ts` for polling and long-running servers, if you want them separate from app code.
- **Do** put `plugins` and a durable `session.store` in `createBot()` for edge deployments; the config file never runs there.
- **Don't** list the same plugin in both places expecting two instances. The `createBot()` copy replaces the config one.
- **Don't** put `commands` or your `component`/`router` in `teact.config.ts`; they belong in `createBot()`.
