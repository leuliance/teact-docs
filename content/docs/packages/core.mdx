`@teactjs/core` is the engine. It contains the React reconciler that turns your components into
Telegram output, the runtime that drives a bot (`createBot`), the router, the plugin and
dependency-injection host, and **every hook**. It also re-exports the React primitives you need, so
you rarely import `react` directly. Visual components (`Message`, `Button`, …) live in
[`@teactjs/ui`](/docs/packages/ui); the Telegram transport lives in
[`@teactjs/telegram`](/docs/packages/telegram).

```npm
npm i @teactjs/core react
```

`react` (`^18.0.0 || ^19.0.0`) is a peer dependency. `react-reconciler`, `i18next` and
`react-i18next` are regular dependencies and install automatically.

**When to use**

- Always — every Teact bot imports `createBot` and its hooks from here.
- When you write middleware (`halt`, `compose`), route guards (`redirect`) or a custom adapter
  (the `Adapter` contract).
- When you need translations without the extras of [`@teactjs/i18n`](/docs/packages/i18n)
  (`createI18n`, `useLocale`).

## Quick example

```tsx title="src/index.tsx"
import { createBot, createRouter, useSession, useNavigate } from "@teactjs/core";
import { Message, InlineKeyboard, ButtonRow, Button } from "@teactjs/ui";
import { TelegramAdapter } from "@teactjs/telegram";

function Home() {
  const [session, setSession] = useSession<{ visits?: number }>();
  const visits = (session.visits ?? 0) + 1;
  return (
    <Message text={`Welcome back! Visit #${visits}`}>
      <InlineKeyboard>
        <ButtonRow>
          <Button text="Count again" onClick={() => setSession({ visits })} />
          <Button text="About" route="/about" />
        </ButtonRow>
      </InlineKeyboard>
    </Message>
  );
}

function About() {
  const navigate = useNavigate();
  return (
    <Message text="Built with Teact.">
      <InlineKeyboard>
        <Button text="Back" onClick={() => navigate("/")} />
      </InlineKeyboard>
    </Message>
  );
}

const router = createRouter({
  "/": { component: Home, command: { name: "start", description: "Open the menu" } },
  "/about": { component: About, command: { name: "about", description: "About this bot" } },
});

const bot = createBot({ router, adapter: new TelegramAdapter() });

if (import.meta.main) bot.start();
```

```tsx title="src/index.tsx"
const bot = createBot({
  router,
  adapter: new TelegramAdapter(),
  commands: {
    help: { description: "Show help", handler: "Use /start to open the menu." },
    echo: {
      description: "Echo your words",
      handler: (ctx) => ctx.reply(ctx.args.join(" ") || "Nothing to echo"),
    },
    menu: {
      description: "Open the menu",
      handler: (ctx) =>
        ctx.reply("Where to?", {
          buttons: [[{ text: "Shop", route: "/shop" }, { text: "Docs", url: "https://teact.dev" }]],
        }),
    },
    item: {
      description: "Open an item",
      route: "/",
      deepLink: (args) => `/items/${args[0]}`,
    },
  },
});
```

Command names are matched case-insensitively, and a `@botname` suffix (`/help@my_bot`) is ignored.

### getEnv

Returns the `env` from the most recent `bot.fetch(request, { env })`. Drivers and session stores
accept lazy getters, so a bot created at module scope can reach Workers bindings without importing
`cloudflare:workers`:

```ts title="src/bot.tsx"
import { createBot, getEnv } from "@teactjs/core";
import { TelegramAdapter } from "@teactjs/telegram";
import { storagePlugin } from "@teactjs/storage";
import { D1Driver, d1SessionStore } from "@teactjs/cloudflare";

export const bot = createBot({
  router,
  adapter: new TelegramAdapter(),
  plugins: [storagePlugin({ driver: new D1Driver(() => getEnv<Env>().DB) })],
  session: { store: d1SessionStore(() => getEnv<Env>().DB) },
});
```

### Update lifecycle

For every incoming message or button press:

1. Updates for the same chat are **serialized** — the next waits for the previous to finish
   rendering and sending. Different chats run concurrently.
2. A route button (`__route:<path>`) or a known `/command` marks the chat's screen for reset.
3. Plugin middleware runs, then `teact.config.ts` middleware, then `createBot({ middleware })`.
   `halt(ctx)` stops here and leaves the current screen and its handlers intact.
4. The reset happens; a `handler` command runs its handler, otherwise the tree renders.
5. The tree is wrapped (inside-out) in `Suspense`, an `ErrorBoundary`, each plugin `Provider`, your
   `providers`, then the runtime contexts.
6. The commit is sent or edited according to the navigate mode, and pending session writes are
   awaited before the update finishes.

## Router

```ts
function createRouter<const T extends Record<string, RouteValue>>(
  routes: T,
  options?: CreateRouterOptions,
): RouterConfig;
```

A `RouteValue` is a component, or `{ component, beforeLoad?, command? }`.

<TypeTable
  type={{
    component: { type: 'FunctionComponent<any>', description: 'Screen to render.', required: true },
    beforeLoad: { type: 'RouteGuard', description: 'Runs before the route loads; may redirect, render something else or reply.' },
    command: { type: 'RouteCommand', description: '{ name, description, deepLink? } — registers /name to open this route.' },
  }}
/>

`CreateRouterOptions` has one field, `notFound?: FunctionComponent<any>` (default: a "Page not
found" message that suggests `/start`).

### Matching

- `:name` segments capture one path segment (`[^/]+`).
- More specific routes match first: deeper paths win, and at equal depth a static route beats a
  param route, so `/pokemon/list` is not shadowed by `/pokemon/:id`.
- A trailing slash is ignored (`/pokemon/` matches `/pokemon`).
- The default route is `/`, or the first route if there is no `/`.

### Navigation modes

`useNavigate()(path, { mode })` controls what happens to the previous message:

| `NavigateMode` | Behaviour |
| -------------- | --------- |
| `replace` (default) | Edit the current message in place (falls back to sending when an edit isn't possible, e.g. text → photo). |
| `push` | Keep the old message, send the new one below. |
| `stack` | Strip buttons from the old message, send the new one below. |
| `dismiss` | Strip buttons from the old message, send nothing. |

### Guards

`RouteGuard` is `(ctx: BeforeLoadContext) => void | string | GuardRedirect | GuardComponent | GuardReply | ReactElement`.
`BeforeLoadContext` is `{ path, params, session, reply }`.

| Return value | Effect |
| ------------ | ------ |
| `undefined` | Load the route. |
| a path string / `redirect('/x')` | Redirect (the same path is treated as "load"). |
| `{ redirect, message?, buttons? }` | Redirect. |
| `{ component }` | Render that component instead. |
| a JSX element | Render it instead. |
| `reply(text, { buttons })` | Send a message with route/url buttons (`GuardButton`: `{ text, route?, url? }`). |

```tsx title="src/router.tsx"
import { createRouter, redirect } from "@teactjs/core";

export const router = createRouter(
  {
    "/": Home,
    "/orders/:id": {
      component: Order,
      beforeLoad: ({ session, reply }) => {
        if (!session.userId)
          return reply("Please log in first.", {
            buttons: [[{ text: "Log in", route: "/login" }, { text: "Menu", route: "/" }]],
          });
      },
    },
    "/admin": {
      component: Admin,
      beforeLoad: ({ session }) => (session.isAdmin ? undefined : redirect("/")),
    },
  },
  { notFound: NotFound },
);
```

<Callout type="warn" title="Guards fail closed">
A guard that throws renders the `notFound` screen and logs the error; it never falls through to the
protected component. More than 5 chained redirects are treated as a loop and also render `notFound`.
Components rendered by a guard can still read `useParams()`.
</Callout>

### Typed params

```ts
const { id } = useParams<"/pokemon/:id">();               // { id: string }
const { tid, mid } = useParams<"/team/:tid/member/:mid">(); // { tid: string; mid: string }
const { id: x } = useParams<{ id: string }>();             // explicit shape
const params = useParams();                                 // Record<string, string>
```

`PathParams<P>` is the type that extracts `:param` names from a template.

## Sessions

`useSession<T>()` returns `[session, update]`. `update(patch)` merges the patch into the session and
queues a write to the store. Writes for one update are chained in call order and awaited before the
update finishes, so they are not lost on serverless.

The default store is `MemorySessionStore(ttl = 24 h)`. Its extra members are `size` and
`cleanup()` (drop expired entries). Sessions are keyed per chat as `<platform>:<chatId>`.

`SessionStore` is the contract for custom stores:

```ts
interface SessionStore {
  get(key: string): Promise<SessionData | null>;
  set(key: string, data: SessionData): Promise<void>;
  delete(key: string): Promise<void>;
}
```

Durable stores ship in [`@teactjs/storage`](/docs/packages/storage) (`createSessionStore`) and the
database packages.

## Middleware

`Middleware` is `(ctx: BotContext, next: () => Promise<void>) => Promise<void>`. `compose` calls
`next()` for you when a middleware returns without calling it, so "not calling next" does **not**
block an update — call `halt(ctx)` instead.

```ts title="src/middleware.ts"
import { halt, type Middleware } from "@teactjs/core";

const ADMINS = ["123456789"];

export const adminsOnly: Middleware = async (ctx) => {
  if (!ADMINS.includes(ctx.userId)) halt(ctx);
};

export const timing: Middleware = async (ctx, next) => {
  const t = Date.now();
  await next();
  console.log(`${ctx.chatId} handled in ${Date.now() - t} ms`);
};
```

Calling `next()` explicitly after `halt(ctx)` still continues the chain. `next()` called twice in one
middleware throws `next() called multiple times`.

## Conversations and forms

### useConversation

Declarative mode takes a `StepsConfig` (`Record<string, StepDef>`):

| `StepDef` | Behaviour |
| --------- | --------- |
| `{ prompt: string; validate?: Validator }` | Wait for free text, validate it. |
| `{ ask: string; options: (string \| { text, value })[][] }` | Inline buttons; typing text instead shows "Please pick an option from the buttons above." |
| `{ render: (done, actions: StepActions) => ReactElement }` | Custom step; call `done(value?)` (default value `'done'`). |

Imperative mode (`useConversation()` or `useConversation({ validate })`) exposes `has`, `get`,
`set`, `clear`, `prompt(key, text)`, `ask(key, text, options)` and `waitFor(key)`.

`ConversationState` also has `step`, `current`, `complete`, `isWaiting`, `data`, `lastError`,
`render(onComplete?)`, `back()`, `goTo(key)`, `canGoBack()` and `reset()`. `complete` is always
`false` in imperative mode.

```tsx title="src/screens/Feedback.tsx"
import { useConversation } from "@teactjs/core";
import { Message } from "@teactjs/ui";

export function Feedback() {
  const conv = useConversation({
    name: { prompt: "What's your name?", validate: (v) => v.trim().length >= 2 || "Too short" },
    rating: { ask: "Rate us:", options: [["1", "2", "3"], [{ text: "5 stars", value: "5" }]] },
  });

  return conv.render(() => (
    <Message text={`Thanks ${conv.data.name}! Rating: ${conv.data.rating}`} />
  ));
}
```

When validation fails, the step is shown again prefixed with `⚠️ <error>`.

### Compound components

```tsx
<Conversation>
  <Conversation.Prompt name="name" text="What's your name?" />
  <Conversation.Ask name="color" text="Pick:" options={[["Red", "Blue"]]} />
  <Conversation.Step name="confirm">
```

## Events

`TelegramEvent` is one of `'*'`, `message`, `text`, `photo`, `video`, `audio`, `voice`, `document`,
`sticker`, `contact`, `location`, `venue`, `animation`, `video_note`, `poll`, `poll_answer`,
`callback_query`, `inline_query`, `new_chat_members`, `left_chat_member`, `dice`, `game`,
`web_app_data`, `successful_payment`, `pre_checkout_query`.

`EventContext`: `{ navigate, chatId, userId, user, reply(text), raw }`. `useOn` handlers run in an
effect, at most once per update and event.

```tsx
useOn("contact", (contact, ctx) => {
  ctx.reply(`Got your number: ${contact.phone_number}`);
  ctx.navigate("/thanks");
});

const location = useEventData<{ latitude: number; longitude: number }>("location");
```

## Streaming

`useStream({ throttleMs = 500 })` returns `{ text, isStreaming, stream(source) }`. `stream()` resets
`text`, iterates the async iterable and re-renders at most once per `throttleMs`, with a final flush.
Starting a new stream cancels the previous one. See [Streaming](/docs/guides/streaming).

## The Adapter contract

Platform packages implement `Adapter` so the engine never depends on a specific transport.

| Member | Description |
| ------ | ----------- |
| `name` | Adapter name. |
| `requiresToken?` | `false` for adapters that don't talk to a platform (no token needed). |
| `connect({ token })` | Create the client; does not start receiving. |
| `on(event, handler)` | Subscribe to `'message'` / `'callback_query'`. |
| `send(chatId, output)` | Send an `OutputNode` tree; resolves the message id. |
| `edit(chatId, messageId, output)` | Edit a message in place. |
| `canEdit(output, chatId?)` | Whether `output` can replace the tracked message in place. |
| `clearButtons(chatId, messageId)` | Remove inline buttons. |
| `setCommands(commands)` | Register the command menu. |
| `listen(opts?)` | Start polling or the webhook server (`{ polling?, webhook? }`). |
| `disconnect()` | Stop and clean up. |
| `webhookCallback?(opts?)` | `(Request) => Promise<Response>`; enables `bot.fetch()`. |

`BotContext` carries `chatId`, `userId`, `user` (`User`: `id`, `username?`, `firstName?`,
`lastName?`, `isBot?`, `languageCode?`, `platform`), `platform`, `messageId?`, `text?`,
`callbackData?`, `botUsername?` and `raw`. `OutputNode` is `{ type, props, children }`.

## Behaviour notes

### Plugins from teact.config.ts and createBot()

Plugins from both lists are merged. If a plugin with the same `name` appears in **both**, only the
`createBot()` copy is used (with a warning), so you don't get two driver instances or duplicated
`onStart`/`onStop`. Repeating a plugin **within one list** is intentional and every copy is kept —
for example a per-user and a per-chat `rateLimit`. A plugin whose `onStart` throws is logged and
skipped; the bot still starts.

### Default error screen

Every chat's screen is wrapped in an `ErrorBoundary`. When a render throws, Teact logs the error and
shows `❌ Something went wrong. Please try again, or use /start to restart.`; the next update
rebuilds the screen from scratch. The error message is **not** shown to users, since it can carry
internals such as SQL, paths or tokens. Wrap your own `ErrorBoundary` with a `fallback` to
customize it:

```tsx
<ErrorBoundary fallback={(error, retry) => <Message text="Oops — try again." />}>
  <Profile />
</ErrorBoundary>
```

Suspended components show `⏳ Loading…` until they resolve.

### Button presses on a new process

<Callout type="warn" title="onClick handlers are in memory">
`onClick` handlers live in the memory of the process that rendered the message. If a press arrives
after a restart or on a fresh serverless isolate, Teact re-renders that screen **in place** (editing
the message the button is on) from its initial state, and logs a warning. Route buttons
(`<Button route="/settings" />`) work on any instance; on serverless, prefer them and keep screen
state in `useSession` / `useStorage`.
</Callout>

### Serverless

- `bot.fetch()` rejects a wrong secret with `401` before any work (no `getMe`, no plugin `onStart`).
- With the default `MemorySessionStore`, `bot.fetch()` warns once that sessions will not persist
  between requests. Pass a durable store.
- `.env` and `teact.config.ts` are only read where a filesystem exists; on Cloudflare Workers both
  are skipped, so configure plugins in `createBot()`.
- The adapter must implement `webhookCallback`, otherwise `bot.fetch()` throws.

### Hot reload

`bot.start()` stops the previous instance kept on `globalThis` before starting, so `teact dev`
restarts don't leave two pollers running.
