title: "@teactjs/redis"
description: API reference for the Redis storage driver, durable session store and plugin — ioredis (incl. Cluster), node-redis, Bun's built-in client and Upstash (edge).
---

`@teactjs/redis` stores Teact state in Redis: a `RedisDriver` for `storagePlugin`, a durable
`redisSessionStore`, and `redisPlugin` + `useRedis` to reach your client from components. It adapts
four client libraries behind one small interface, none of them a hard dependency, and keeps
counters exact across instances with an atomic `incr`.

```npm
npm i @teactjs/redis @teactjs/storage ioredis
```

Install **one** client: `ioredis`, `redis` (node-redis v4/v5) or `@upstash/redis`. Skip it on Bun if
you use Bun's built-in `RedisClient`. Peer dependencies: `@teactjs/core`, `@teactjs/storage`,
`@teactjs/plugin-sdk`, `react`; the clients are optional peers (`ioredis ^5`, `redis ^4 || ^5`,
`@upstash/redis ^1`).

Or let the CLI install and wire it: `teact add redis --client ioredis` (`ioredis` | `redis` |
`upstash` | `bun`).

**When to use**

- Several bot instances (or a restart-heavy deploy) need to share chat state and sessions.
- You want exact rate limits and analytics across instances (`incr`).
- On edge runtimes, with Upstash over HTTP.

| Client | Runtime | Detection |
| ------ | ------- | --------- |
| [`ioredis`](https://github.com/redis/ioredis) (`Redis`, `Cluster`) | Node / Bun | automatic, or `fromIoredis(client)` |
| [`redis`](https://github.com/redis/node-redis) (node-redis v4/v5) | Node / Bun | automatic, or `fromNodeRedis(client)` |
| Bun's built-in `RedisClient` / `Bun.redis` | Bun | automatic, or `fromBunRedis(client)` |
| [`@upstash/redis`](https://github.com/upstash/redis-js) (HTTP) | Workers, Vercel Edge, Deno, Node | automatic, or `fromUpstash(client)` |

## Quick example

<Tab value="ioredis">

```ts title="src/db.ts"
import Redis from "ioredis";
import { storagePlugin } from "@teactjs/storage";
import { RedisDriver, redisPlugin, redisSessionStore } from "@teactjs/redis";

export const redis = new Redis(process.env.REDIS_URL!);
export const redisDriver = new RedisDriver({ client: redis, namespace: "mybot:" });

export const plugins = [redisPlugin({ client: redis, closeOnStop: true }), storagePlugin({ driver: redisDriver })];
export const sessionStore = redisSessionStore({ client: redis, namespace: "mybot:" });
```

| `fromBunRedis` | function | `(client: BunRedisLike) => RedisCommands` | Adapt Bun's `RedisClient`. |
| `fromUpstash` | function | `(client: UpstashLike, opts?: FromUpstashOptions) => RedisCommands` | Adapt `@upstash/redis`. |

`IoredisLike`, `NodeRedisLike`, `BunRedisLike`, `UpstashLike`, `FromUpstashOptions`.

## RedisDriver

<TypeTable
  type={{
    client: { type: 'AnyRedisClient', description: 'ioredis, node-redis v4+, Bun RedisClient, @upstash/redis, or a RedisCommands object. Raw clients are auto-detected.', required: true },
    clientKind: { type: "'ioredis' | 'node-redis' | 'bun' | 'upstash'", description: 'Force an adapter instead of auto-detecting.' },
    namespace: { type: 'string', description: 'Prefix prepended to every Redis key (e.g. "mybot:"). keys()/entries() never include it; clear() only touches keys under it.', default: "''" },
    closeClient: { type: 'boolean', description: 'Close the client in driver.close() (called by storagePlugin on stop).', default: 'false' },
  }}
/>

The driver exposes `commands` (the normalized `RedisCommands`) and implements `get`, `set`,
`delete`, `has`, `keys`, `clear`, `entries`, `close` and — when the client adapter supports it —
`incr`.

### How data is stored

- **Values** are JSON strings, readable by any Redis tool. Reads also tolerate plain non-JSON
  strings written by other code. `set(key, undefined)` deletes the key.
- **TTL**: `set(key, value, { ttl: ms })` becomes `SET key value PX ms`. `0`, negative, `NaN` or
  `Infinity` mean no expiry.
- **Counters**: `incr(key, by = 1, { ttl? })` runs one Lua script: `INCRBY` for integers,
  `INCRBYFLOAT` for fractions, and `PEXPIRE` only when the key was just created. A non-finite `by`
  throws. `@teactjs/plugins` uses it for exact rate limits and analytics across instances.
- **Prefix queries** use `SCAN … MATCH <escaped prefix>*` with `COUNT 250`, never `KEYS`.
  `entries()` is one SCAN pass plus one `MGET` (parallel `GET`s if the client has no `mget`).
- **`clear(prefix?)`** deletes while scanning, in `DEL` batches of 500. It never runs `FLUSHDB`.

<Callout type="warn" title="clear() without a namespace">
Without a `namespace`, `driver.clear()` deletes every key in the database. Always set a `namespace`
when the database is shared with other bots or apps.
</Callout>

### ioredis Cluster

An ioredis `Cluster` is detected automatically (`isCluster === true` and `nodes()`): prefix queries
`SCAN` every master and multi-key reads and deletes go key by key, so you never hit `CROSSSLOT`.

```ts
import { Cluster } from "ioredis";
import { RedisDriver } from "@teactjs/redis";

new RedisDriver({ client: new Cluster([{ host: "redis-1", port: 6379 }]), namespace: "mybot:" });
```

Use the driver's `namespace`, not ioredis' `keyPrefix`: `keyPrefix` is not applied to `SCAN`
patterns or results, so prefix queries would miss your keys.

### Upstash specifics

Upstash JSON-parses values on read by default. `fromUpstash` re-encodes them so the driver sees
exactly what it stored (a stored string `"42"` comes back as `"42"`, not `42`), and disambiguates a
stored `null` with `EXISTS`. If you created the client with `automaticDeserialization: false` and
detection fails, pass `fromUpstash(client, { automaticDeserialization: false })`.

### Closing

The driver never closes a client you pass in unless `closeClient: true`. Closing is idempotent
across Teact — a client shared by a driver with `closeClient: true` and `redisPlugin({ closeOnStop: true })`
is closed once. ioredis uses `quit()`, node-redis `close()` (v5) or `quit()` (v4), Bun `close()`;
Upstash has nothing to close.

  type={{
    client: { type: 'AnyRedisClient', description: 'Same as RedisDriver.', required: true },
    clientKind: { type: 'RedisClientKind', description: 'Force an adapter.' },
    namespace: { type: 'string', description: 'Key namespace.' },
    closeClient: { type: 'boolean', description: 'Same as RedisDriver.', default: 'false' },

  }}
/>

```ts
createBot({
  session: { store: redisSessionStore({ client: redis, namespace: "mybot:", ttl: 30 * 24 * 3600_000 }) },
});
```

Equivalent to `createSessionStore(new RedisDriver(opts), { prefix, ttl })` from
[`@teactjs/storage`](/docs/packages/storage). A session for chat 42 lives at
`mybot:session:telegram:42`.

## redisPlugin and useRedis

<TypeTable
  type={{
    client: { type: 'C extends AnyRedisClient', description: 'Your client, exposed unchanged through useRedis() / useService("redis").', required: true },
    closeOnStop: { type: 'boolean', description: 'Close the client when the bot stops.', default: 'false' },

```tsx title="src/screens/Leaderboard.tsx"
import { useState, useEffect, useBot } from "@teactjs/core";
import { Message, InlineKeyboard, Button } from "@teactjs/ui";
import { useRedis } from "@teactjs/redis";
import type Redis from "ioredis";

export function Leaderboard() {
  const redis = useRedis<Redis>();
  const { userId } = useBot();
  const [top, setTop] = useState<string[]>([]);

  useEffect(() => {
    redis.zrevrange("scores", 0, 4, "WITHSCORES").then(setTop);
  }, []);

  return (
    <Message text={top.length ? `Top players:\n${top.join(" ")}` : "Loading…"}>
      <InlineKeyboard>
        <Button text="+1 point" onClick={() => redis.zincrby("scores", 1, userId)} />
      </InlineKeyboard>
    </Message>
  );
}
```

## Custom clients: RedisCommands

`RedisDriver` only talks to this interface. Implement it for any other client (a proxy, a mock) and
mark it with `markNormalized`:

<TypeTable
  type={{
    'get(key)': { type: 'Promise<string | null>', description: 'Raw stored text, or null.', required: true },
    'mget(keys)': { type: 'Promise<Array<string | null>>', description: 'Optional. Many keys in one round trip.' },
    'set(key, value, ttlMs?)': { type: 'Promise<void>', description: 'Store; expire after ttlMs (SET … PX).', required: true },
    'del(keys)': { type: 'Promise<void>', description: 'Delete at least one key.', required: true },
    'scan(pattern)': { type: 'AsyncIterable<string[]>', description: 'SCAN … MATCH pattern, one batch per page (duplicates allowed).', required: true },
    'incrby(key, by, ttlMs?)': { type: 'Promise<number>', description: 'Optional. Atomic increment; ttl only on creation. Without it the driver has no incr.' },
    'close()': { type: 'Promise<void>', description: 'Optional. Close the connection.' },
  }}
/>

```ts title="test/fake-redis.ts"
import { markNormalized, RedisDriver, type RedisCommands } from "@teactjs/redis";

const data = new Map<string, string>();
const fake: RedisCommands = markNormalized({
  get: async (k) => data.get(k) ?? null,
  set: async (k, v) => void data.set(k, v),
  del: async (keys) => keys.forEach((k) => data.delete(k)),
  async *scan(pattern) {
    const prefix = pattern.replace(/\*$/, "").replace(/\\(.)/g, "$1");
    yield [...data.keys()].filter((k) => k.startsWith(prefix));
  },
});

export const driver = new RedisDriver({ client: fake });
```

An unmarked object is also accepted when it has `get`/`set`/`del` and its `scan` is an
`async function*`. Anything else that isn't recognized throws `Could not recognize the Redis client`
— wrap it with the matching `from*` helper or pass `clientKind`.

Detection rules (`detectRedisClient`): node-redis has a camel-cased `mGet`; Bun is an instance of
`Bun.RedisClient` or has `send()` without `scanStream`; ioredis has `scanStream()` (or is a
`Cluster`); Upstash has an HTTP `client.request()` and `exists()`.

## Serverless and edge

- TCP clients don't work on Cloudflare Workers or Vercel Edge; use `@upstash/redis`. Create the
  client once per isolate, at module scope — not per request.
- Writes are awaited before `bot.fetch()` resolves, so nothing is lost when the isolate freezes.
- On long-running servers (ioredis, node-redis, Bun), create one client and reuse it.
