MongoDB storage for Teact bots: a `MongoDriver` for `storagePlugin`, a durable session store, and a
plugin that exposes your database to components. It uses the official
[`mongodb`](https://www.npmjs.com/package/mongodb) driver as an optional peer dependency and only
relies on the structural shape of `Collection`, `Db` and `MongoClient`.

```bash
bun add @teactjs/mongodb @teactjs/storage mongodb
```

With the CLI: `teact add mongodb`.

## Exports

| Export | Kind | Description |
| ------ | ---- | ----------- |
| `MongoDriver` | class | `AsyncStorageDriver` — one document per key. |
| `mongoSessionStore` | function | `mongoSessionStore({ db \| client \| collection, collectionName?, prefix?, ttl? })` → `SessionStore`. |
| `mongoPlugin` | plugin | Registers the `Db` as the `'mongo'` service (and the client as `'mongoClient'`). |
| `useMongo` | hook | `useMongo<Db>()` → the registered database. |
| `escapeRegex`, `DEFAULT_COLLECTION` | utils | Regex escaping for prefix lookups; `'teact_storage'`. |
| `MONGO_SERVICE`, `MONGO_CLIENT_SERVICE` | constants | `'mongo'`, `'mongoClient'`. |
| `MongoDriverOptions`, `MongoSessionStoreOptions`, `MongoPluginOptions`, `MongoStorageDoc` | types | Options and document shape. |

## Storage driver

```ts
import { MongoClient } from "mongodb";
import { createBot } from "@teactjs/core";
import { storagePlugin } from "@teactjs/storage";
import { MongoDriver } from "@teactjs/mongodb";

const client = await new MongoClient(process.env.MONGO_URL!).connect();
const driver = new MongoDriver({ db: client.db("mybot") }); // collection 'teact_storage'
await driver.ensureIndexes();                                // TTL index (once, idempotent)

createBot({ plugins: [storagePlugin({ driver })] /* ... */ });
```

Pass any one of:

- `collection` — a `Collection`.
- `db` (and optionally `collectionName`, default `'teact_storage'`).
- `client` (and optionally `dbName` and `collectionName`). Set `closeClient: true` to close it when
  the bot stops.

### How data is stored

Each key is one document:

```js
{ _id: "telegram:12345:visits", value: { n: 3 }, expiresAt: ISODate("…") /* only with a ttl */ }
```

- **`value`** is native BSON, so you can query and index it like any other field.
- **Prefix lookups**, which the storage plugin runs on every update, use an anchored, escaped
  `^prefix` regex on `_id`, served by the `_id` index. `entries()` is a single `find()`.
- **Expiry**: `set(key, value, { ttl })` writes `expiresAt`. Expired documents are filtered out on
  read immediately. `ensureIndexes()` creates `{ expiresAt: 1 }` with `expireAfterSeconds: 0`, so
  MongoDB deletes them in the background (its TTL monitor runs about once a minute).

## Sessions

```ts
import { mongoSessionStore } from "@teactjs/mongodb";

createBot({
  session: {
    store: mongoSessionStore({
      db: client.db("mybot"),
      collectionName: "sessions",
      ttl: 30 * 24 * 3600_000, // optional: idle sessions expire after 30 days
    }),
  },
});
```

If you use `ttl`, create the TTL index on that collection once, e.g. with
`new MongoDriver({ db, collectionName: "sessions" }).ensureIndexes()`.

## Plugin: use the database in components

```tsx
import type { Db } from "mongodb";
import { mongoPlugin, useMongo } from "@teactjs/mongodb";

createBot({
  plugins: [mongoPlugin({ client, dbName: "mybot" })], // or mongoPlugin({ db })
});

function Profile() {
  const db = useMongo<Db>();
  // db.collection("users").findOne(...) inside a handler or effect
}
```

With a `client`, the plugin closes it when the bot stops (`closeOnStop`, default `true`).

## Serverless notes

- Create the `MongoClient` once at module scope and reuse it. Don't connect per request.
- Writes are awaited before `bot.fetch()` resolves, so they are durable even when the function
  freezes after the response.
- The `mongodb` driver needs TCP sockets: Node, Bun, Vercel/Netlify Node functions and AWS Lambda
  are fine. On Cloudflare Workers it needs `nodejs_compat` and connection reuse is limited, so
  [`@teactjs/cloudflare`](/docs/packages/cloudflare) (D1) or Upstash Redis are usually a better fit.

## Do / Don't

- **Do** call `ensureIndexes()` once (at startup or in a migration) when you use `ttl`.
- **Do** share one `MongoClient` between `mongoPlugin` and `MongoDriver`.
- **Don't** open a new connection per update.
