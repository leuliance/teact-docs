Streaming shows a long answer while it is still being produced, by editing one message as new
text arrives. It is how chat assistants "type" their reply. In Teact, `useStream` from
`@teactjs/core` collects chunks from any async iterable (an LLM SDK stream, a generator, a
paginated API) and re-renders the screen at a throttled rate. Each re-render edits the message in
place.

## A first stream

```tsx title="src/screens/Assistant.tsx"
import { useState, useStream } from "@teactjs/core";
import { Message, InlineKeyboard, Button } from "@teactjs/ui";

async function* fakeCompletion(answer: string) {
  for (const word of answer.split(" ")) {
    await new Promise((r) => setTimeout(r, 80));
    yield word + " ";
  }
}

export function Assistant() {
  const { text, isStreaming, stream } = useStream({ throttleMs: 250 });
  const [question, setQuestion] = useState<string | null>(null);

  const ask = (q: string, answer: string) => {
    if (isStreaming) return;
    setQuestion(q);
    stream(fakeCompletion(answer));
  };

  const body = question
    ? `🧑 ${question}\n\n🤖 ${text}${isStreaming ? " ▌" : ""}`
    : "🤖 Ask me something.";

  return (
    <Message text={body}>
      <InlineKeyboard columns={1}>
        <Button text="What is Teact?" onClick={() => ask("What is Teact?", "Teact lets you build Telegram bots with React components and hooks.")} />
        <Button text="🏠 Menu" route="/" />
      </InlineKeyboard>
    </Message>
  );
}
```

## How it works

1. `stream(source)` clears `text`, sets `isStreaming` to `true` and starts reading `source` in the
   background. It returns immediately (`void`), so don't `await` it.
2. Each chunk is appended to an internal buffer. The first chunk is shown right away; after that,
   `text` is updated at most once every `throttleMs`.
3. Every update re-renders the component, and Teact edits the message in place (the normal
   [edit rules](/docs/guides/components#edit-or-send) apply: a text screen after a button press is
   edited).
4. When the source ends, the full text is set and `isStreaming` becomes `false`.

Calling `stream()` again while a stream is running starts the new one and abandons the old one:
the old source is no longer read after its next chunk, and its text is discarded.

### Choosing throttleMs

Each re-render is a Telegram `editMessageText` call, and Telegram rate-limits edits. The adapter
retries rate-limited calls automatically, but fewer edits mean smoother output. Values from 250 to
1000 ms work well; the default is 500.

## Streaming from an LLM

Any SDK that exposes an async iterator works. Map its events to plain strings with a small
generator:

```ts title="src/ai/stream.ts"
// Shape-agnostic: adapt the field access to your SDK's chunk type.
export async function* textChunks(events: AsyncIterable<{ delta?: string }>) {
  for await (const event of events) {
    if (event.delta) yield event.delta;
  }
}
```

```tsx
const { text, isStreaming, stream } = useStream({ throttleMs: 400 });

<Button text="Summarise" onClick={() => stream(textChunks(llm.stream({ prompt: "Summarise my week" })))} />;
```

Remember the [4096-character limit](/docs/guides/components#telegram-limits): longer text is
truncated with `…`. Ask the model for shorter answers, or send the rest as follow-up messages once
`isStreaming` is `false`.

## Streaming inside a conversation

Imperative conversations from `@teactjs/telegram` have their own `conversation.stream(source)`:

```ts
import { defineConversation } from "@teactjs/telegram";

defineConversation("ask", async (conversation) => {
  const question = await conversation.prompt("What would you like to know?");
  await conversation.stream(answerStream(question));
  await conversation.send("Anything else? Send /ask again.");
});
```

`conversation.stream()` uses `@grammyjs/stream` when `streamPlugin()` is registered. Without the
plugin it falls back to sending the first chunk and editing the message at most every 500 ms.
`useStream` does not need the plugin.

```tsx title="src/index.tsx"
import { TelegramAdapter, conversationsPlugin, streamPlugin } from "@teactjs/telegram";

createBot({
  adapter: new TelegramAdapter(),
  router,
  plugins: [conversationsPlugin(), streamPlugin()],
});
```

## Recipes

### Regenerate and stop

```tsx
const { text, isStreaming, stream } = useStream();
const [prompt, setPrompt] = useState("Write a haiku about bots");

<InlineKeyboard>
  {!isStreaming && <Button text="🔁 Regenerate" onClick={() => stream(generate(prompt))} />}
  {isStreaming && <Button text="⏹ Stop" onClick={() => stream(emptyStream())} />}
</InlineKeyboard>;

// Starting an empty stream abandons the running one.
async function* emptyStream() {}
```

`Stop` replaces the running stream with an empty one, which also clears `text`. To keep the
partial answer, copy it into state before stopping.

### Progress for a long job

Streams don't have to be language models. Yield status lines from any long task:

```ts
async function* importProgress(files: string[]) {
  for (const [i, file] of files.entries()) {
    await importFile(file);
    yield `✅ ${file} (${i + 1}/${files.length})\n`;
  }
  yield "\nDone!";
}
```

### Handle errors in the source

An error thrown by the source is not caught for you, and `isStreaming` stays `true`. Catch inside
your generator and yield a message instead:

```ts
async function* safe(source: AsyncIterable<string>) {
  try {
    for await (const chunk of source) yield chunk;
  } catch {
    yield "\n\n⚠️ The answer was interrupted. Tap Regenerate to try again.";
  }
}

stream(safe(llmStream));
```

## Serverless

<Callout type="warn" title="Streaming needs a long-running process">
  On Cloudflare Workers, Vercel Edge and other serverless runtimes, `bot.fetch()` returns once the
  first render is delivered, and the instance may be frozen right after. Chunks that arrive later
  are never rendered. Run streaming bots with `bot.start()` (polling or a webhook server). See
  [Deployment](/docs/guides/deployment#edge-checklist).
</Callout>

## Gotchas

- `stream()` returns `void`. Read progress from `text` and `isStreaming`.
- Stream into a **text** screen. If the screen is media (a photo with a caption), each update sends
  a new message instead of editing.
- Start streams from a button press: the message with the button is then edited. A stream started
  by an incoming text message sends the first render as a new message, then edits that one.
- `useStream` state belongs to the component. Navigating away mid-stream unmounts it; the source
  keeps being read in the background but nothing is shown.
