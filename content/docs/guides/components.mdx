`@teactjs/ui` holds the 36 components you build screens from. Each one renders to a Telegram
Bot API call: `<Message>` becomes `sendMessage`, `<Photo>` becomes `sendPhoto`, `<Poll>` becomes
`sendPoll`, and so on. Components are plain React function components, so you compose them with
state, hooks and conditionals like any React UI.

Engine pieces (hooks, router, `createBot`) live in `@teactjs/core`. This page only covers
components.

## A first screen

```tsx title="src/screens/Welcome.tsx"
import { useState, useBot } from "@teactjs/core";
import { Message, Bold, InlineKeyboard, ButtonRow, Button } from "@teactjs/ui";

export function Welcome() {
  const { user } = useBot();
  const [count, setCount] = useState(0);

  return (
    <Message>
      Hi <Bold>{user.firstName ?? "there"}</Bold>! You tapped {count} times.
      <InlineKeyboard>
        <ButtonRow>
          <Button text="-1" onClick={() => setCount((c) => c - 1)} />
          <Button text="+1" variant="primary" onClick={() => setCount((c) => c + 1)} />
        </ButtonRow>
        <Button text="Settings" route="/settings" />
        <Button text="Website" url="https://example.com" />
      </InlineKeyboard>
    </Message>
  );
}
```

  buttons={[["-1", "▸ +1"], ["Settings"], [{ text: "Website", url: "https://example.com" }]]}
/>

Tapping `+1` re-renders the component and Teact edits the same message in place.

## How a tree becomes a message

### One render, one message

A screen's whole render output becomes **one** Telegram API call. If you return several
siblings in a fragment, Teact merges them into a single payload: text from every element is
concatenated in order, and a media or poll element anywhere in the tree decides the send method.

```tsx
// Sends ONE message: "❌ Failed\nTimeout\nTry again?"
<>
  <Alert variant="error" title="Failed">Timeout</Alert>
  <Message text="Try again?" />
</>
```

Use fragments to compose text blocks (alerts, lists, dividers) into one message. To send several
separate messages, use the media hooks (`useMedia`, `usePhoto`, …; see
[Hooks](/docs/guides/hooks#media-senders)) or router navigation with `mode: "push"`.

### Edit or send

Teact tracks the last message it sent to each chat and decides per render whether to edit it or
send a new one:

| Situation | Result |
| --- | --- |
| The update is an incoming message (text, `/command`, shared contact, …) | New message |
| A button press re-renders a text screen and the tracked message is text | Edit in place |
| The new tree is media, a poll, a location, a contact or a venue | New message |
| The tracked message is media and the new tree is text | New message (Telegram can't turn one into the other) |
| The tree contains `<ReplyKeyboard>` or `<ReplyKeyboardRemove>` | New message |
| `navigate(path, { mode })` with `push`, `stack` or `dismiss` | See [navigation modes](/docs/guides/router#navigation-modes) |

An edit replaces the text and the inline keyboard together. If the new tree has no
`<InlineKeyboard>`, the edit removes the old buttons. Telegram's "message is not modified" error
is ignored, so re-rendering identical output is harmless.

After a restart, or on a fresh serverless instance, Teact has no tracked message. A button press
then edits the message the button lives on instead of sending a duplicate.

### Telegram limits

| Limit | Teact behaviour |
| --- | --- |
| Message text: 4096 characters | Truncated to 4095 characters plus `…`, with a console warning |
| Caption (any media): 1024 characters | Truncated the same way |
| `<MediaGroup>`: 2–10 items | 1 item is sent as a plain photo/video; more than 10 are dropped with a warning; 0 sends nothing |
| `<Poll>`: at least 2 options | Warning; Telegram rejects the poll |
| `<Poll.Quiz>`: valid `correctOptionId` | Warning when missing or out of range |
| A `<Message>` with buttons but no text | Not sent; Telegram needs text to attach a keyboard. A warning explains why |

Lengths are counted on the final string, including the HTML tags that formatting components
generate.

### SuspenseFallback

A ready-made loading message for `<Suspense>` boundaries. It renders a `<Message>` with its text.

<TypeTable
  type={{

  }}

```tsx
import { Suspense } from "@teactjs/core";
import { SuspenseFallback } from "@teactjs/ui";

<Suspense fallback={<SuspenseFallback text="Fetching your profile…" />}>
  <Profile />
</Suspense>;
```

Teact already wraps every screen in a `<Suspense>` with a default loading message. Add your own

## Buttons & keyboards

### InlineKeyboard

The container for inline buttons, attached under a message. Put it inside `<Message>` or inside a
media component such as `<Photo>`.

<TypeTable
  type={{
    columns: { type: 'number', description: 'Arrange direct children into rows of this many buttons. Without it, each bare `<Button>` is its own row.' },
    children: { type: 'ReactNode', description: '`<Button>`, `<Button.WebApp>` and `<ButtonRow>` elements.' },
  }}
/>

There are three ways to lay buttons out:

```tsx
// 1. A bare <Button> is its own row
<InlineKeyboard>
  <Button text="Top" onClick={onTop} />
  <Button text="Bottom" onClick={onBottom} />
</InlineKeyboard>

// 2. columns={n} builds an n-column grid
<InlineKeyboard columns={2}>
  <Button text="Kanto" route="/region/kanto" />
  <Button text="Johto" route="/region/johto" />
  <Button text="Hoenn" route="/region/hoenn" />
</InlineKeyboard>

// 3. <ButtonRow> for explicit rows
<InlineKeyboard>
  <ButtonRow>
    <Button text="Yes" onClick={onYes} />
    <Button text="No" onClick={onNo} />
  </ButtonRow>
</InlineKeyboard>
```

### Button

An inline button. It throws if it is not inside an `<InlineKeyboard>`. Also available as

<TypeTable
  type={{
    text: { type: 'string', required: true, description: 'Button label.' },
    url: { type: 'string', description: 'Open this URL when tapped. No callback is sent.' },
    route: { type: 'string', description: 'Navigate to this route when tapped. `:param` segments are filled from `params`.' },
    params: { type: 'Record<string, string | number>', description: 'Values for `:param` segments in `route`.' },
    conversation: { type: 'string', description: 'Enter the named conversation registered with `conversationsPlugin` (from `@teactjs/telegram`).' },
    onClick: { type: 'string | (() => void)', description: 'A function to run on tap, or a raw `callback_data` string.' },
    variant: { type: "'default' | 'primary' | 'destructive' | 'outline'", default: "'default'", description: 'Adds a text prefix to the label.' },
  }}
/>

#### Action precedence

A button carries exactly one action. When you pass several props, the first match in this order
wins:

1. **`url`**: a link button. No callback data.
2. **`route`** (+ `params`): navigates to the route. The path is encoded in the callback data, so
   it works after a restart and on any serverless instance.
3. **`conversation`**: enters a named imperative conversation.
4. **`onClick` function**: runs the function in the process that rendered the button.
5. **`onClick` string**: sent as raw `callback_data`. Read it with `useCallbackData()`.
6. **None of the above**: the label itself is sent as `callback_data`.

```tsx
<Button text="Docs" url="https://example.com/docs" />          {/* opens a link */}
<Button text="Open #25" route="/pokemon/:id" params={{ id: 25 }} /> {/* navigates to /pokemon/25 */}
<Button text="Feedback" conversation="feedback" />             {/* enters a conversation */}
<Button text="Like" onClick={() => setLiked(true)} />          {/* runs a handler */}
<Button text="Delete" onClick="delete:25" />                   {/* raw callback_data */}
```

<Callout type="warn" title="onClick lives in memory">
  Function handlers are stored in the memory of the process that rendered the message. After a
  restart, or when a press lands on a fresh serverless instance, the handler is gone: Teact logs a
  warning and renders the bot again from its starting state (in a router app, the default route),
  editing the pressed message. Use `route` buttons (and keep state in `useSession` or `useStorage`)
  for buttons that must keep working.
</Callout>

### ReplyKeyboard

A custom keyboard that replaces the phone keyboard under the input field. Tapping a button sends
its text as a normal message, which you read with `useText()`.

<TypeTable
  type={{
    resizeKeyboard: { type: 'boolean', default: 'true', description: 'Shrink the keyboard to fit its buttons.' },
    oneTimeKeyboard: { type: 'boolean', description: 'Hide the keyboard after one tap.' },
    placeholder: { type: 'string', description: 'Placeholder shown in the input field while the keyboard is open.' },
    isPersistent: { type: 'boolean', description: 'Keep the keyboard visible even when the user hides it.' },
    children: { type: 'ReactNode', description: 'Rows and reply buttons.' },
  }}
/>

The building blocks, all of which throw outside a `<ReplyKeyboard>`:

| Component | Alias | Props | Sends |
| --- | --- | --- | --- |
| `ReplyRow` | `ReplyKeyboard.Row` | `children` | One row of buttons |
| `ReplyButton` | `ReplyKeyboard.Button` | `text: string` | The button text as a message |
| `RequestContactButton` | `ReplyKeyboard.RequestContact` | `text: string` | The user's phone contact (after they confirm) |
| `RequestLocationButton` | `ReplyKeyboard.RequestLocation` | `text: string` | The user's current location |

A bare reply button outside a `ReplyRow` becomes its own row.

```tsx title="src/screens/MainMenu.tsx"
import { useText } from "@teactjs/core";
import { Message, ReplyKeyboard } from "@teactjs/ui";

export function MainMenu() {
  const text = useText();
  const reply = text === "Help" ? "Send /start to begin." : "Choose an option below.";

  return (
    <Message text={reply}>
      <ReplyKeyboard placeholder="Choose…">
        <ReplyKeyboard.Row>
          <ReplyKeyboard.Button text="Orders" />
          <ReplyKeyboard.Button text="Help" />
        </ReplyKeyboard.Row>
        <ReplyKeyboard.RequestLocation text="📍 Send my location" />
      </ReplyKeyboard>
    </Message>
  );
}
```

### ReplyKeyboardRemove

Removes the active reply keyboard from the chat. It takes no props. Put it in the next message you
send after you no longer need the keyboard.

```tsx
<Message text="Thanks, got your contact.">
  <ReplyKeyboardRemove />
</Message>
```

<Callout type="warn" title="One keyboard per message">
  Telegram allows one `reply_markup` per message. When a tree contains several, Teact uses
  `<ReplyKeyboardRemove>` first, then `<ReplyKeyboard>`, then `<InlineKeyboard>`; the others are
  dropped. To remove a reply keyboard and show inline buttons, send them as two messages.
</Callout>

## Media

All media components take `src`: an HTTPS URL or a Telegram `file_id` you received earlier.
Components with `children` accept formatting components (rendered into the caption) and an
`<InlineKeyboard>`.

The `caption` prop is plain text. To format a caption, put `<Bold>`, `<Italic>` or `<Code>`
children inside the media element instead; they switch the caption to HTML and are appended after
`caption`.

```tsx title="src/screens/PokemonCard.tsx"
import { useParams } from "@teactjs/core";
import { Photo, Bold, InlineKeyboard, Button } from "@teactjs/ui";

export function PokemonCard() {
  const { id } = useParams<"/pokemon/:id">();
  const art = `https://raw.githubusercontent.com/PokeAPI/sprites/master/sprites/pokemon/other/official-artwork/${id}.png`;

  return (
    <Photo src={art} caption={`#${id} `}>
      <Bold>Pikachu</Bold>
      <InlineKeyboard columns={2}>
        <Button text="Comments" route="/pokemon/:id/comments" params={{ id }} />
        <Button text="Back" route="/list" />
      </InlineKeyboard>
    </Photo>
  );
}
```

<TelegramPreview text={"[photo]\n#25 Pikachu"} buttons={[["Comments", "Back"]]} />

  type={{
    text: { type: 'string', required: true, description: 'Toast or alert text.' },
    showAlert: { type: 'boolean', description: 'Show a modal alert with an OK button instead of a toast.' },
  }}
/>

```tsx title="src/screens/Settings.tsx"
import { useNavigate, useSession } from "@teactjs/core";
import { Message, Notification, InlineKeyboard, Button } from "@teactjs/ui";

export function Settings() {
  const navigate = useNavigate();
  const [session, setSession] = useSession<{ darkMode?: boolean }>();

  return (
    <Message text={`Dark mode is ${session.darkMode ? "on" : "off"}.`}>
      <InlineKeyboard>
        <Button
          text="Toggle and save"
          onClick={() => {
            setSession({ darkMode: !session.darkMode });
            navigate("/saved", { mode: "push" });
          }}
        />
      </InlineKeyboard>
    </Message>
  );
}

// Route "/saved": the toast answers the button press, the message is sent below.
export function Saved() {
  return (
    <>
      <Notification text="Saved!" />
      <Message text="Your settings are saved." />
    </>
  );
}
```

<TelegramPreview text="Your settings are saved." notification="Saved!" />

<Callout type="warn" title="Notifications ride on sends">
  The Telegram adapter attaches a notification to the answer when the tree is delivered with a
  **send**. When the press is applied as an in-place **edit** (the default for text screens), the
  notification is not picked up in the current adapter. If the toast matters, deliver that screen
  as a new message (for example `navigate(path, { mode: "push" })`) or show the confirmation in the
  message text.
</Callout>

## Formatting

Formatting components switch the message (or caption) to HTML parse mode and wrap their children
in tags. They work inside `<Message>` and inside media components.

| Component | Alias | Props | Renders |
| --- | --- | --- | --- |
| `Bold` | `Message.Bold` | `children` | `<b>…</b>` |
| `Italic` | `Message.Italic` | `children` | `<i>…</i>` |
| `Code` | `Message.Code` | `language?: string`, `children` | `<code>…</code>`, or `<pre><code class="language-x">…</code></pre>` with `language` |
| `Alert` | – | `variant?`, `title?`, `children` | Icon + title line, then the children, then a line break |
| `List` | – | `ordered?: boolean` (default `false`), `children` | Each child on its own line, prefixed `• ` or `1. ` |
| `ListItem` | `List.Item` | `children` | One list entry |
| `Divider` | – | `char?: string` (default `'─'`), `length?: number` (default `20`) | The character repeated, then a line break |

`Alert` variants and their icons: `info` ℹ️ (default), `warning` ⚠️, `error` ❌, `success` ✅.

```tsx title="src/screens/Summary.tsx"
import { Message, Alert, List, Divider, Bold, Code } from "@teactjs/ui";

export function Summary({ name, items }: { name: string; items: string[] }) {
  return (
    <>
      <Alert variant="success" title="Order placed">
        Thanks, <Bold>{name}</Bold>!
      </Alert>
      <Divider length={12} />
      <List ordered>
        {items.map((item) => (
          <List.Item key={item}>{item}</List.Item>
        ))}
      </List>
      <Message>
        Reference: <Code>A-1042</Code>
      </Message>
    </>
  );
}
```

<TelegramPreview text={"✅ Order placed\nThanks, Ada!\n────────────\n1. Pikachu plush\n2. Poké Ball keyring\nReference: A-1042"} />

### HTML escaping

When formatting components switch a message to HTML, Teact escapes `&`, `<` and `>` in all of your
text: the `text` prop, plain children and the children of formatting components. User input
such as a name like `<script>` is shown literally and cannot break or inject markup.

```tsx
// Sends: Hello <b>&lt;Ada&gt;</b>  (parse_mode HTML)
<Message>
  Hello <Bold>{"<Ada>"}</Bold>
</Message>
```

If you set `parseMode` yourself, the `text` prop is sent **verbatim**: escaping it is your job.

```tsx
// Your own markup, your own escaping
<Message parseMode="HTML" text={`<b>${escapeHtml(userName)}</b> joined`} />
```

<Callout type="error" title="Don't mix Markdown with formatting components">
  Formatting components always emit HTML tags. With `parseMode="Markdown"` or `"MarkdownV2"` on the
  same message, Telegram receives literal `<b>` tags. Use either your own `parseMode` and markup, or
  formatting components, per message.
</Callout>

## Recipes

### Confirm before delete

Keep the "are you sure?" step in local state. Both steps edit the same message.

```tsx title="src/screens/DeleteItem.tsx"
import { useState, useParams, useNavigate } from "@teactjs/core";
import { Message, Bold, InlineKeyboard, ButtonRow, Button } from "@teactjs/ui";
import { deleteItem } from "../api";

export function DeleteItem() {
  const { id } = useParams<"/items/:id/delete">();
  const navigate = useNavigate();
  const [confirming, setConfirming] = useState(false);

  if (!confirming) {
    return (
      <Message>
        Delete item <Bold>{id}</Bold>?
        <InlineKeyboard>
          <Button text="Delete" variant="destructive" onClick={() => setConfirming(true)} />
          <Button text="Cancel" route="/items/:id" params={{ id }} />
        </InlineKeyboard>
      </Message>
    );
  }

  return (
    <Message text="This cannot be undone. Are you sure?">
      <InlineKeyboard>
        <ButtonRow>
          <Button
            text="Yes, delete"
            variant="destructive"
            onClick={async () => {
              await deleteItem(id);
              navigate("/items");
            }}
          />
          <Button text="No" onClick={() => setConfirming(false)} />
        </ButtonRow>
      </InlineKeyboard>
    </Message>
  );
}
```

### Ask for the user's contact

```tsx title="src/screens/ShareContact.tsx"
import { useEventData } from "@teactjs/core";
import { Message, ReplyKeyboard, ReplyKeyboardRemove } from "@teactjs/ui";

export function ShareContact() {

  );
}
```

### Raw callback data for many similar buttons

A string `onClick` lets one screen handle many buttons without registering a handler per button.
The data is not tied to process memory, but after a restart the press is rendered by your
starting screen, so in router apps prefer route buttons for navigation.

```tsx
import { useCallbackData } from "@teactjs/core";

function Ratings() {
  const data = useCallbackData(); // e.g. "rate:4" after a tap
  const rating = data?.startsWith("rate:") ? Number(data.slice(5)) : null;

  return (
    <Message text={rating ? `You rated ${rating}/5` : "Rate us:"}>
      <InlineKeyboard columns={5}>
        {[1, 2, 3, 4, 5].map((n) => (
          <Button key={n} text={"⭐".repeat(n)} onClick={`rate:${n}`} />
        ))}
      </InlineKeyboard>
    </Message>
  );
}
```

Telegram limits `callback_data` to 64 bytes, so keep raw strings and route paths short.
