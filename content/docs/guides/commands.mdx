Commands are the `/start`, `/help` and `/settings` messages users send to your bot. In Teact a
command either **opens a route** (and renders a screen) or **runs a handler** (and replies
directly). Commands also fill Telegram's command menu, the list users see when they type `/`.

You can define commands in two places, and both end up in the same table:

- `createBot({ commands })` for standalone and handler commands.
- `command:` on a route in `createRouter` for commands that open that route.

## A first set of commands

```tsx title="src/index.tsx"
import { createBot, createRouter, type CommandDef } from "@teactjs/core";
import { TelegramAdapter } from "@teactjs/telegram";
import { Home, Settings, PokemonCard } from "./screens";

const router = createRouter({
  "/": Home,
  "/settings": Settings,
  "/pokemon/:id": PokemonCard,
});

const commands: Record<string, CommandDef> = {
  start: {
    description: "Open the menu",
    route: "/",
    deepLink: ([payload]) => (payload?.startsWith("poke-") ? `/pokemon/${payload.slice(5)}` : "/"),
  },
  settings: { description: "Your settings", route: "/settings" },
  help: {
    description: "Show help",
    handler: ({ reply }) =>
      reply("What do you need help with?", {
        buttons: [
          [{ text: "⚙️ Settings", route: "/settings" }, { text: "🏠 Menu", route: "/" }],
          [{ text: "📖 Docs", url: "https://example.com/docs" }],
        ],
      }),
  },
  ping: { description: "Check the bot is alive", handler: "pong 🏓" },
};

export const bot = createBot({ adapter: new TelegramAdapter(), router, commands });

if (import.meta.main) bot.start();
```

## How a command is handled

When a text message starts with `/`, Teact:

<Steps>
<Step>
### Parses it

The first word is the command and the rest, split on whitespace, are the arguments.
`/start poke-25` gives `start` and `["poke-25"]`. A `@botname` suffix (`/help@my_bot`, common in
groups) is stripped, and the name is lowercased before lookup.
</Step>
<Step>
### Looks it up

If no command has that name, the message is not treated as a command: the current screen
re-renders with it, like any other text. If it matches, the chat's component tree is reset so the
command starts from a clean state.
</Step>
<Step>
### Runs the middleware pipeline

Plugin middleware, then your middleware, run as for any update. A middleware can call
`halt(ctx)` to stop the command; the reset is deferred until the end of the pipeline, so a halted
command leaves the current screen and its buttons intact.
</Step>
<Step>
### Renders or replies

A command with a `handler` runs the handler in place of rendering. Otherwise Teact renders the
router at the command's path: the `deepLink` result when the command has arguments, else `route`,
else the router's default route.
</Step>
</Steps>

## Route or handler?

| Use a route command when… | Use a handler command when… |
| --- | --- |
| The command opens a screen with state, buttons and follow-up interaction | The answer is one message (help text, status, a link) |
| You want guards, params and deep links | You need the raw arguments and no UI state |
| The same screen is reachable from buttons | It should run without mounting any component |

Handler replies are plain text. Their buttons can navigate (`route`) or open links (`url`); for
anything richer, use a route.

## Co-located route commands

Put the command next to the route it opens:

```tsx title="src/router.tsx"
export const router = createRouter({
  "/": {
    component: MainMenu,
    command: { name: "start", description: "Open the showcase" },
  },
  "/list": {
    component: PokemonList,
    command: { name: "pokedex", description: "Browse the Pokédex" },
  },
  "/pokemon/:id": PokemonCard,
});
```

A route `command` takes `name`, `description` and an optional `deepLink`; its `route` is the path
it sits on. When `createBot` starts, it merges route commands first and then
`createBot({ commands })`, so an explicit command with the same name wins.

A common split is to co-locate every command that opens a screen, and keep only handler commands
(`/help`, `/ping`) in `createBot`.

## Deep links

Telegram links of the form `https://t.me/<bot>?start=<payload>` send `/start <payload>` when the
user taps **Start**. The payload arrives as `args[0]`; resolve it with `deepLink`:

```ts
start: {
  description: "Open the menu",
  route: "/",
  deepLink: ([payload]) => {
    if (payload?.startsWith("poke-")) return `/pokemon/${payload.slice(5)}`;
    if (payload?.startsWith("order-")) return `/orders/${payload.slice(6)}`;
    return "/";
  },
},
```

`deepLink` works on any command, not only `start`: with
`deepLink: ([id]) => "/pokemon/" + id`, the message `/open 25` opens that card. The resolved path goes through normal
matching and guards; an unknown path renders `notFound`. More in
[Router → Deep links](/docs/guides/router#deep-links).

## Registering the command menu

The menu users see when they type `/` is set with Telegram's `setMyCommands`. Teact builds it from
every command's name and `description`.

<Tabs items={['Polling / webhook server', 'Serverless']}>
<Tab value="Polling / webhook server">

`bot.start()` registers the menu on every start. Nothing to do. If registration fails (for
example a network error), Teact logs a warning and keeps running.

</Tab>
<Tab value="Serverless">

`bot.fetch()` does **not** register the menu, to avoid a Telegram call on every cold start. Run
`bot.setCommands()` once after each deploy that changes commands. It resolves to the number of
commands registered:

```bash
bun -e "import { bot } from './src/index'; console.log(await bot.setCommands())"
```

See [Deployment → Register the command menu](/docs/guides/deployment#register-the-command-menu).

</Tab>
</Tabs>

## Commands and middleware

Every command goes through the middleware pipeline, including handler commands: the handler takes
the place of the render step. Rate limits, maintenance mode, loggers and error reporters apply to
commands, and `halt(ctx)` stops them.

```ts title="src/middleware/admin-commands.ts"
import { halt, type Middleware } from "@teactjs/core";

const ADMINS = new Set(["123456789"]);
const ADMIN_COMMANDS = ["/broadcast", "/stats"];

export const adminCommands: Middleware = async (ctx) => {
  const isAdminCommand = ADMIN_COMMANDS.some((c) => ctx.text?.split(/[\s@]/)[0] === c);
  if (isAdminCommand && !ADMINS.has(ctx.userId)) {
    await ctx.raw.reply("That command is for admins.");
    halt(ctx);
  }
};

// createBot({ middleware: [adminCommands], ... })
```

Because the reset is deferred until the end of the pipeline, a halted command leaves the user's
current screen and its buttons working. See
[Middleware & plugins → The pipeline](/docs/guides/middleware-plugins#the-pipeline).

## Reading the command in a component: useCommand

`useCommand()` returns `{ name, args }` for the update that opened the screen, or `null`.

```tsx title="src/screens/Search.tsx"
import { useState, useCommand } from "@teactjs/core";
import { Message } from "@teactjs/ui";

export function Search() {
  const cmd = useCommand();
  // Capture the arguments once: useCommand() is only set during the command's own update.
  const [query] = useState(() => cmd?.args.join(" ") ?? "");

  return <Message text={query ? `Results for "${query}"…` : "Send /search <words>"} />;
}
```

What `useCommand()` returns:

| Update | Value |
| --- | --- |
| A route command (`/search pikachu`) | `{ name: "search", args: ["pikachu"] }` |
| A route button press | `{ name: "", args: [] }` |
| Any other update (text, button handlers, shared media) | `null` |

Handler commands never render, so they never reach `useCommand()`.

## Recipes

### Aliases for one screen

Point several commands at one route and branch on the name:

```tsx
const commands: Record<string, CommandDef> = {
  orders: { description: "Your orders", route: "/orders" },
  history: { description: "Order history", route: "/orders" },
};

function Orders() {
  const cmd = useCommand();
  const [showAll] = useState(() => cmd?.name === "history");
  return <Message text={showAll ? "All orders" : "Open orders"} />;
}
```

### A status command with live data

Handler functions can be async and fetch what they need:

```ts
status: {
  description: "Service status",
  handler: async ({ reply }) => {
    const res = await fetch("https://status.example.com/api.json");
    const { ok } = (await res.json()) as { ok: boolean };
    await reply(ok ? "✅ All systems normal" : "⚠️ We're investigating an issue", {
      buttons: [[{ text: "Status page", url: "https://status.example.com" }]],
    });
  },
},
```

### Commands that start a conversation

Imperative conversations from `@teactjs/telegram` can be started by a command of their own:

```ts
defineConversation("feedback", {
  command: "feedback",
  async handler(conversation) {
    const text = await conversation.prompt("What do you think of the bot?");
    await conversation.send(`Thanks! You said: ${text}`);
  },
});
```

The conversations plugin intercepts `/feedback` before Teact's pipeline, so it does not go through
Teact middleware and is not added to the menu. To list it in the menu, also declare it in
`commands` or on a route. See [Conversations](/docs/guides/conversations#imperative-conversations).

## Gotchas

<Callout type="warn" title="Use lowercase names">
  Incoming command names are lowercased before lookup, so a command registered as `myOrders` never
  matches. Telegram's menu also only accepts lowercase letters, digits and underscores.
</Callout>

- A command resets the chat's component tree: any form or conversation in progress on the current
  screen is discarded.
- An unregistered `/something` is ordinary text. The current screen re-renders and can read it
  with `useText()`.
- `handler` wins over `route`: a command with both never renders the route.
