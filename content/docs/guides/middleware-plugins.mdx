## Middleware

Runs on every update before rendering. If a middleware returns without calling `next`, the runtime
calls it for you — simple loggers work without manual `next`.

```ts
import type { Middleware } from "@teactjs/core";

const logger: Middleware = async (ctx) => {
  console.log(ctx.chatId, ctx.text);
};

const bot = createBot({
  middleware: [logger],
  // ...
});
```

Explicit `next()` when you need code after the chain:

```ts
const timer: Middleware = async (ctx, next) => {
  const t = Date.now();
  await next();
  console.log(Date.now() - t, "ms");
};
```

## Halting an update

Because `next()` is called automatically, *not* calling it can't block an update. Call
`halt(ctx)` instead: once the current middleware returns, no further middleware runs and the
component is not rendered.

```ts
import { halt, type Middleware } from "@teactjs/core";

const adminsOnly: Middleware = async (ctx) => {
  if (!ADMINS.includes(ctx.userId)) halt(ctx);
};

const noBots: Middleware = async (ctx) => {
  if (ctx.user.isBot) halt(ctx);
};
```

`isHalted(ctx)` tells you whether an update was halted (useful in a timing/logging middleware after
`await next()`). Calling `next()` explicitly after `halt(ctx)` still continues the chain.

## Pipeline order

For each update the runtime runs, in order:

1. Plugin middleware, in `plugins` order.
2. Your `middleware` array.
3. The final step: render the component (or the route), **or** run the command's inline `handler`.

Commands defined with a `handler` (`commands: { ping: { handler: "pong" } }`) go through the same
pipeline as everything else, so rate limits, maintenance mode, logging and error reporting apply to
them too, and a halted update never reaches the handler. See [Commands](/docs/guides/commands).

## TeactPlugin

```ts
import type { TeactPlugin } from "@teactjs/core";

const myPlugin: TeactPlugin = {
  name: "analytics",
  onStart: (bot) => {},
  middleware: (ctx, next) => next(),
  Provider: ({ children }) => children,
  onStop: () => {},
};
```

Register in `createBot({ plugins: [myPlugin] })` or via `defineConfig` / `teact.config.ts`. To author
reusable plugins with config defaults and DI services, use
[`@teactjs/plugin-sdk`](/docs/packages/plugin-sdk).

## Ready-made plugins

[`@teactjs/plugins`](/docs/packages/plugins) ships production middleware built on `halt`:
`rateLimit`, `logger`, `maintenance`, `chatFilter`, `ignoreOld`, `errorReporter`, `analytics`,
`featureFlags`, plus `createBroadcaster` for mass messaging.

```ts
import { logger, errorReporter, rateLimit } from "@teactjs/plugins";

createBot({
  component: App,
  plugins: [
    logger(),
    errorReporter({ report: (err) => console.error(err) }),
    rateLimit({ window: 2000, limit: 3, onLimited: "⏳ Slow down!" }),
  ],
});
```

Add them with the CLI: `teact add rate-limit logger`.

## Debug

`createBot({ debug: true })` logs updates, renders, and middleware for troubleshooting.
