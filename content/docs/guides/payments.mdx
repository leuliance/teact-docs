Telegram has native payments: the bot sends an **invoice**, Telegram shows a checkout sheet, and
after the user pays, the bot receives a **successful payment** message. `useInvoice` from
`@teactjs/core` sends the invoice for the current chat and tracks its status in the component.

You can charge in two ways:

- **Telegram Stars** (`currency: "XTR"`) for digital goods. No payment provider is needed.
- **A payment provider** (Stripe, Chapa and others connected in @BotFather → Payments), in a
  regular currency such as `USD` or `ETB`. You get a provider token from BotFather.

## A first invoice

```tsx title="src/screens/Store.tsx"
import { useInvoice } from "@teactjs/core";
import { Message, Alert, InlineKeyboard, ButtonRow, Button } from "@teactjs/ui";

export function Store() {
  const invoice = useInvoice({
    title: "Premium Pokédex",
    description: "Unlock all 151 Pokémon, stats and exclusive features",
    payload: "premium-pokedex-v1",
    providerToken: process.env.PAYMENT_PROVIDER_TOKEN ?? "",
    currency: "USD",
    prices: [{ label: "Premium access", amount: 499 }], // $4.99 in cents
    photoUrl: "https://example.com/premium.png",
    needEmail: true,
    sendEmailToProvider: true,
  });

  if (invoice.status === "success") {
    return (
      <Message text={`✅ Payment received. Thank you!\nCharge ID: ${invoice.receipt?.telegramPaymentChargeId}`}>
        <InlineKeyboard>
          <Button text="🏠 Menu" route="/" />
        </InlineKeyboard>
      </Message>
    );
  }

  if (invoice.status === "failed") {
    return (
      <>
        <Alert variant="error" title="Payment failed">
          {invoice.error ?? "Unknown error"}
        </Alert>
        <Message text="Check the payment configuration and try again.">
          <InlineKeyboard>
            <ButtonRow>
              <Button text="🔄 Retry" onClick={invoice.send} />
              <Button text="🏠 Menu" route="/" />
            </ButtonRow>
          </InlineKeyboard>
        </Message>
      </>
    );
  }

  return (
    <Message text={`💎 Premium Pokédex — $4.99${invoice.status === "pending" ? "\n\n⏳ Invoice sent below." : ""}`}>
      <InlineKeyboard>
        <Button text="💳 Buy Premium" onClick={invoice.send} />
      </InlineKeyboard>
    </Message>
  );
}
```

## The payment lifecycle

<Steps>
<Step>
### `send()` sends the invoice

`status` becomes `"pending"` and the invoice appears in the chat as its own message, with
Telegram's **Pay** button. If the call fails, `status` becomes `"failed"` and `error` holds the
message.
</Step>
<Step>
### The user pays

Telegram shows its checkout sheet. Before charging, Telegram sends the bot a pre-checkout query;
the Telegram adapter **approves it automatically**.
</Step>
<Step>
### The payment arrives

Telegram sends a message containing `successful_payment`. The current screen re-renders with it,
and if its `invoice_payload` matches your `payload`, `status` becomes `"success"` and `receipt` is
filled. Because it is an incoming message, the success screen is sent as a new message.
</Step>
</Steps>

## Telegram Stars

For digital goods, charge in Stars. Set `currency: "XTR"`, leave `providerToken` empty, and give
the amount in Stars:

```tsx
const invoice = useInvoice({
  title: "100 coins",
  description: "In-game coins",
  payload: "coins-100",
  providerToken: "",
  currency: "XTR",
  prices: [{ label: "100 coins", amount: 50 }], // 50 Stars
});

<Button text="⭐ Buy for 50 Stars" onClick={invoice.send} />;
```

With any other currency, an empty `providerToken` fails before calling Telegram, with
`status: "failed"` and an error that tells you to get a token from @BotFather or use `"XTR"`.

## Recipes

### Record payments in middleware

The hook only sees a payment while the screen that sent the invoice is mounted in the same
process. To record every payment, even if the user navigated away or the bot restarted, handle
`successful_payment` in a middleware too:

```ts title="src/middleware/payments.ts"
import type { Middleware } from "@teactjs/core";
import { db } from "../db";

export const recordPayments: Middleware = async (ctx) => {
  const payment = ctx.raw?.message?.successful_payment;
  if (!payment) return;

  await db.payments.insert({
    userId: ctx.userId,
    payload: payment.invoice_payload,
    amount: payment.total_amount,
    currency: payment.currency,
    telegramChargeId: payment.telegram_payment_charge_id,
  });
};

// createBot({ middleware: [recordPayments], ... })
```

The update continues to the screen afterwards, so `useInvoice` still flips to `success`.

### One payload per product

`payload` is how a payment is matched to a hook. Use a distinct payload per product (and, if you
need it, per order: `order-${orderId}`), so two invoices on one screen never confuse each other:

```tsx
const monthly = useInvoice({ ...base, payload: "pro-monthly", prices: [{ label: "Monthly", amount: 499 }] });
const yearly = useInvoice({ ...base, payload: "pro-yearly", prices: [{ label: "Yearly", amount: 4999 }] });
```

## Gotchas

<Callout type="warn" title="Pre-checkout is always approved">
  The Telegram adapter answers every pre-checkout query with "OK" and doesn't forward it to your
  components, so you can't reject a checkout (for example when stock ran out) from Teact. Validate
  before calling `send()`, and refund through your provider if a charge can't be fulfilled.
</Callout>

- **Hook state is in memory.** `status` and `receipt` live in the component. A `/command`, a route
  button, a restart or a fresh serverless instance loses them; the middleware recipe is the
  reliable record.
- **Amounts are integers** in the smallest unit: cents for USD, Stars for XTR.
- **Test with a test provider.** BotFather offers test tokens for most providers, so you can run
  the whole flow without real money.
